# MCP 2026-07-28 Dual-Era Modernization Implementation Plan

> **For agentic workers:** Execute this plan separately from branch attachment work. Track progress with the checkboxes. Do not invoke `using-superpowers`, commit, push, create a pull request, or alter remotes unless Bobby directly authorizes that action.

**Goal:** Add MCP 2026-07-28 support to TokenSave's local stdio server while preserving byte-compatible behavior for legacy clients through `2025-11-25`.

**Architecture:** The server will classify each request as modern or legacy. Modern requests carry protocol version and client capabilities in `params._meta`; legacy processes continue using `initialize`. `server/discover` will provide the required stdio era probe. Response construction will add modern `resultType` and server metadata only for modern requests, leaving legacy payloads unchanged.

**Tech Stack:** Rust 2021, serde_json, Tokio, MCP JSON-RPC 2.0 over stdio.

## Global Constraints

- This plan does not fix branch attachment, reload binaries, or modify host configuration. Those changes belong to `2026-09-20-branch-reopen-reconnect-mcp-latest.md`.
- Preserve every legacy protocol revision currently listed in `SUPPORTED_PROTOCOL_VERSIONS`.
- A legacy `initialize` request selects legacy behavior. A request carrying modern `_meta` selects modern behavior.
- Do not infer modern capabilities from earlier requests. MCP 2026-07-28 declares capabilities per request.
- Do not implement optional Tasks, MCP Apps, Skills, subscriptions, or multi-round-trip extensions in this change.
- Do not send `notifications/message` for a modern request unless its `_meta` opts into a log level.
